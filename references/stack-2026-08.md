# Stack digest — as of 2026-08

Condensed from the August 2026 research. Principles age slowly; product names, versions, and prices age fast: verify before pinning (see SKILL.md, step 3). Full text with sources: `research-2026-08.md`.

## Language: Python vs. TypeScript

- **Python** remains the default for agent logic, RAG, evals, data pipelines: the deepest ecosystem (PyTorch, Hugging Face, vLLM, LangGraph, PydanticAI, LlamaIndex, DSPy); research lands in Python first. Package management solved with `uv`. Weakness: no native frontend.
- **TypeScript** wins at the product/UI edge: one language across the stack, streaming chat, end-to-end type safety. Per GitHub Octoverse 2025, the most-used language on GitHub for the first time in August 2025. Weakness: thinner for ML-heavy work; LangGraph.js lags.
- **The common production pattern:** Python backend (agent logic) + TypeScript frontend (Next.js/React). For purely internal tools, Python alone is enough.
- **Vercel** = two things: the open-source **Vercel AI SDK** (TS library, v6 June 2026; streaming, structured output, tool-loop agents, MCP; runs anywhere) and the **Vercel platform** (hosting/PaaS, framework-shaped lock-in, bandwidth price jumps). The SDK does not need the platform.

## Code-first agent frameworks

**Python — recommended**
- **LangGraph** (1.0 GA 2025-10): graph/state machine, persistence, checkpoints, human-in-the-loop. The production default for complex stateful workflows; a 2–3-week learning curve.
- **PydanticAI** (V1 2025-09, V2 2026-06): type-safe, lean, structured output, native MCP/A2A, Logfire/OTel. The recommended starting point for ~90% of cases. Pattern: PydanticAI for agent logic + LangGraph for orchestration where needed.
- Provider-native SDKs (OpenAI Agents SDK, Claude Agent SDK, Google ADK, AWS Strands): fine when deliberately committing to one provider/cloud.

**Python — with caution**
- **CrewAI**: fast to prototype, becomes opaque and expensive in multi-agent pipelines. Prototyping yes, critical production rather not.
- **smolagents**: minimal, strong for local models/research, not for enterprise (no state, HITL, observability).
- **LangChain "Classic"** as an orchestrator is obsolete — integrations still usable, orchestration in LangGraph.
- **AutoGen / Semantic Kernel** separately: merged into Microsoft Agent Framework 1.0 (GA 2026-04) — build new work there.

**TypeScript**
- **Vercel AI SDK v6**: the UI/toolkit layer, default for chat/in-product AI in Next.js.
- **Mastra**: a full TS agent framework (agents, workflows, memory, evals, RAG), Apache 2.0, Series A 2026-04. The TS-native production pick.
- **LangGraph.js**: exists, lags behind Python.

## Standards and building blocks

- **MCP** (Model Context Protocol): the de-facto standard for tool/context integration, Linux Foundation governance; per the MCP blog (2025-12) over 97M monthly SDK downloads, ~10,000 active servers; spec 2026-07-28 with a stateless core. Python SDK 2.0: `MCPServer` instead of `FastMCP`. Build your own tools as MCP servers.
- **A2A** (agent-to-agent): v1.0 2026-04-09 under the Linux Foundation, 150+ organizations, SDKs in 5 languages. Mature as a protocol; in practice mostly PoC outside large enterprises.
- **Structured output/tool calling**: Pydantic (Python) or Zod (TS) as the base; PydanticAI validates and retries automatically.
- **Observability**: Langfuse (open source, self-hostable, part of ClickHouse since 2026-01, OTel-based) — the obvious pick for GDPR/self-hosted; alternatives LangSmith, Arize Phoenix, Helicone, Portkey, Logfire.
- **Gateways/routers**: LiteLLM (open source, self-hostable, virtual keys/budgets/fallbacks, Langfuse integration), OpenRouter (hosted, 300+ models), Portkey (gateway + guardrails).
- **Vector DBs**: pgvector as the default up to ~5–50M vectors; Qdrant for metadata-heavy filtering/high throughput; Weaviate for hybrid/multimodal; Chroma for prototypes; LanceDB for edge/embedded. The DB choice = 5–10% of RAG quality.

## Self-hosted / open source

- **Serving**: vLLM (production), SGLang (prefix-heavy loads); Hugging Face TGI in maintenance mode since 2025-12; Ollama for prototypes/homelab; LM Studio desktop; llama.cpp for granular control.
- **Models with tool calling**: Qwen3 family (30B-A3B sweet spot on 24 GB), gpt-oss 20B/120B (Apache 2.0), Llama, Mistral Small/Medium, DeepSeek (large).
- **Hardware**: 16 GB VRAM → 8–12B; 24 GB → 30B-A3B/32B Q4; 80 GB → 70B FP8 / gpt-oss-120b; flagships → multi-GPU.
- **When**: compliance, high predictable throughput, data sovereignty, no rate limits. Not purely for cost — break-even only at billions of tokens/month. Often sensible: hybrid (self-hosted base load, API for peaks).

## GDPR / EU data residency

- **Hyperscaler EU regions** (Bedrock Frankfurt/Ireland/Paris, Azure EU, GCP EU) with DPA; residual CLOUD Act risk remains.
- **EU providers**: Mistral (FR, EU residency by default), IONOS AI Model Hub (DE, OpenAI-compatible, open models, DPA), STACKIT (Schwarz Group, DE), Aleph Alpha, OVHcloud, Scaleway, Exoscale.
- **Self-hosting** as the strongest option; **zero data retention** on some APIs; LiteLLM self-hosted keeps data in-house.
- **Claude in the EU** only via Bedrock EU or Vertex EU, not the Anthropic API directly (as of 2026-08 — verify).

## Do not build new work on these (2026)

- OpenAI **Assistants API** — sunset 2026-08-26 → Responses API.
- **AutoGen / Semantic Kernel** separately → Microsoft Agent Framework.
- **LangChain Classic** as an orchestrator → LangGraph or PydanticAI.
- **smolagents** for enterprise production.
- OpenAI **Agent Builder/AgentKit** (visual) — being discontinued (unavailable after 2026-11-30) → Agents SDK.
- Excessive multi-agent framing: ~40% of "agent" tasks are one model call with structured output.
- Self-hosting purely for cost without a compliance or volume argument.

## Watch

MCP spec evolution (stateless core, Apps/Tasks), A2A production readiness, Mastra/PydanticAI maturity, the EU sovereign cloud framework in procurement, new open models with strong tool calling.
