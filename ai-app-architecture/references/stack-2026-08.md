## Sprache: Python vs. TypeScript

- **Python** bleibt Default für Agent-Logik, RAG, Evals, Datenpipelines: tiefstes Ökosystem (PyTorch, Hugging Face, vLLM, LangGraph, PydanticAI, LlamaIndex, DSPy), Forschung erscheint zuerst in Python. Paketmanagement mit `uv` gelöst. Schwäche: kein natives Frontend.
- **TypeScript** gewinnt an der Produkt-/UI-Kante: eine Sprache über den Stack, Streaming-Chat, End-to-End-Typsicherheit. Laut GitHub Octoverse 2025 im August 2025 erstmals meistgenutzte Sprache auf GitHub. Schwäche: ML-schwere Arbeit dünner, LangGraph.js hinkt hinterher.
- **Übliches Produktionsmuster:** Python-Backend (Agent-Logik) + TypeScript-Frontend (Next.js/React). Für rein interne Tools reicht Python allein.
- **Vercel** = zwei Dinge: das quelloffene **Vercel AI SDK** (TS-Bibliothek, v6 Juni 2026, Streaming, Structured Output, Tool-Loop-Agents, MCP; läuft überall) und die **Vercel-Plattform** (Hosting/PaaS, framework-shaped Lock-in, Preissprünge bei Bandbreite). Das SDK braucht die Plattform nicht.

## Code-first Agent-Frameworks

**Python – empfehlenswert**
- **LangGraph** (1.0 GA 2025-10): Graph/State-Machine, Persistenz, Checkpoints, Human-in-the-Loop. Produktions-Default für komplexe stateful Workflows; 2–3 Wochen Lernkurve.
- **PydanticAI** (V1 2025-09, V2 2026-06): typsicher, schlank, Structured Output, native MCP/A2A, Logfire/OTel. Empfohlener Startpunkt für ~90 % der Fälle. Muster: PydanticAI für Agent-Logik + LangGraph für Orchestrierung, wo nötig.
- Anbieternative SDKs (OpenAI Agents SDK, Claude Agent SDK, Google ADK, AWS Strands): gut bei bewusster Bindung an einen Anbieter/eine Cloud.

**Python – mit Vorsicht**
- **CrewAI**: schneller Prototyp, wird bei Multi-Agent-Pipelines opak und teuer. Prototyping ja, kritische Produktion eher nicht.
- **smolagents**: minimal, stark für lokale Modelle/Research, nicht für Enterprise (kein State, HITL, Observability).
- **LangChain "Classic"** als Orchestrator veraltet – Integrationen nutzbar, Orchestrierung in LangGraph.
- **AutoGen / Semantic Kernel** getrennt: in Microsoft Agent Framework 1.0 (GA 2026-04) zusammengeführt – dort neu entwickeln.

**TypeScript**
- **Vercel AI SDK v6**: UI-/Toolkit-Schicht, Default für Chat-/In-Product-AI in Next.js.
- **Mastra**: vollständiges TS-Agent-Framework (Agents, Workflows, Memory, Evals, RAG), Apache 2.0, Series A 2026-04. Der TS-native Produktions-Pick.
- **LangGraph.js**: existiert, hinkt Python hinterher.

## Standards und Bausteine

- **MCP** (Model Context Protocol): De-facto-Standard für Tool-/Kontext-Anbindung, Linux-Foundation-Governance; laut MCP-Blog (2025-12) über 97 Mio. monatliche SDK-Downloads, ~10.000 aktive Server; Spec 2026-07-28 mit stateless Core. Python-SDK 2.0: `MCPServer` statt `FastMCP`. Eigene Tools als MCP-Server bauen.
- **A2A** (Agent-to-Agent): v1.0 2026-04-09 unter Linux Foundation, 150+ Organisationen, SDKs in 5 Sprachen. Reif am Protokoll, in der Praxis meist noch PoC außerhalb großer Enterprises.
- **Structured Output/Tool Calling**: Pydantic (Python) bzw. Zod (TS) als Basis; PydanticAI validiert und retryt automatisch.
- **Observability**: Langfuse (Open Source, self-hostbar, seit 2026-01 Teil von ClickHouse, OTel-basiert) – naheliegend für DSGVO/self-hosted; Alternativen LangSmith, Arize Phoenix, Helicone, Portkey, Logfire.
- **Gateways/Router**: LiteLLM (Open Source, self-hostbar, virtuelle Keys/Budgets/Fallbacks, Langfuse-Integration), OpenRouter (hosted, 300+ Modelle), Portkey (Gateway + Guardrails).
- **Vektor-DBs**: pgvector Default bis ~5–50 Mio. Vektoren; Qdrant bei metadaten-schwerem Filtering/hohem Durchsatz; Weaviate für Hybrid/Multimodal; Chroma Prototyp; LanceDB Edge/embedded. DB-Wahl = 5–10 % der RAG-Qualität.

## Self-hosted / Open Source

- **Serving**: vLLM (Produktion), SGLang (prefix-schwere Lasten); Hugging Face TGI seit 2025-12 im Maintenance-Modus; Ollama Prototyp/Homelab; LM Studio Desktop; llama.cpp granulare Kontrolle.
- **Modelle mit Tool-Calling**: Qwen3-Familie (30B-A3B Sweet Spot auf 24 GB), gpt-oss 20B/120B (Apache 2.0), Llama, Mistral Small/Medium, DeepSeek (groß).
- **Hardware**: 16 GB VRAM → 8–12B; 24 GB → 30B-A3B/32B Q4; 80 GB → 70B FP8 / gpt-oss-120b; Flaggschiffe → Multi-GPU.
- **Wann**: Compliance, hoher planbarer Durchsatz, Datenhoheit, keine Rate-Limits. Nicht rein aus Kostengründen – Break-even erst bei Milliarden Tokens/Monat. Häufig sinnvoll: Hybrid (self-hosted Grundlast, API für Spitzen).

## DSGVO / EU-Datenresidenz

- **Hyperscaler EU-Regionen** (Bedrock Frankfurt/Irland/Paris, Azure EU, GCP EU) mit AVV/DPA; CLOUD-Act-Restrisiko bleibt.
- **EU-Anbieter**: Mistral (FR, EU-Residency by default), IONOS AI Model Hub (DE, OpenAI-kompatibel, offene Modelle, AVV), STACKIT (Schwarz-Gruppe, DE), Aleph Alpha, OVHcloud, Scaleway, Exoscale.
- **Self-Hosting** als stärkste Option; **Zero-Data-Retention** bei manchen APIs; LiteLLM self-hosted hält Daten im Haus.
- **Claude in der EU** nur über Bedrock EU oder Vertex EU, nicht über die Anthropic-API direkt (Stand 2026-08 – prüfen).

## Nicht mehr neu darauf setzen (2026)

- OpenAI **Assistants API** – Sunset 2026-08-26 → Responses API.
- **AutoGen / Semantic Kernel** getrennt → Microsoft Agent Framework.
- **LangChain Classic** als Orchestrator → LangGraph oder PydanticAI.
- **smolagents** für Enterprise-Produktion.
- OpenAI **Agent Builder/AgentKit** (visuell) – wird eingestellt (nicht mehr verfügbar ab 2026-11-30) → Agents SDK.
- Übermäßiges Multi-Agent-Framing: ~40 % der "Agent"-Aufgaben sind ein Modellaufruf mit Structured Output.
- Self-Hosting rein aus Kostengründen ohne Compliance- oder Volumen-Argument.
